PTCGPB 플러그인 사용법

docs\Plugin\README.md의 HTML판 - 내용은 동일하다.

이 문서와 예제 코드는 저장소 루트의 Plugins\가 아니라 docs\Plugin\에 있다(2026-08-09 이동) - 예제라도 실제로 스캔되는 Plugins\ 폴더에 있으면 실수로 켜질 위험이 있어서다. 예제를 써보려면 docs\Plugin\examples\의 원하는 폴더를 통째로 복사해서 저장소 루트의 Plugins\ 폴더 안에 붙여넣을 것 - Plugins\<복사한 폴더명>\plugin.ini와 main.ahk가 그대로 살아있어야 한다.

저장소 루트의 Plugins\ 폴더 아래 하위 폴더 하나가 플러그인 하나다. 봇을 시작할 때마다(StartBot) PTCGPB.ahk의 PluginEngine_GenerateManifest()가 이 폴더를 스캔해서, 문제없는 플러그인만 Scripts\_plugins.g.ahk에 인스턴스화 코드까지 같이 생성해 워커(1.ahk 및 그 복제본 2.ahk, 3.ahk, ...)가 로드하게 만든다.

최소 구성

Plugins\
  MyPlugin\
    plugin.ini
    main.ahk

plugin.ini:

[Plugin]
Name=MyPlugin
Class=MyPlugin
Main=main.ahk
Enabled=1
  • Name: 폴더명과 반드시 동일해야 한다. 다르면 로더가 그냥 건너뛴다(Scripts\_plugins.g.ahk에 안 실림, Logs\Plugins.txt에 사유 기록).
  • Class: 신규 키 - main.ahk 안 어떤 클래스를 쓸지 지정한다. 클래스명은 Name(폴더명)과 달라도 되고 자유롭게 지어도 된다.
  • Main: 진입 파일. 생략하면 main.ahk.
  • Enabled: 0으로 두면 폴더를 안 지우고도 끌 수 있다. 생략 시 1.
  • Instances (선택): 쉼표로 인스턴스 번호를 나열하면 그 번호에서만 훅이 등록된다(예: Instances=3,5). 생략하면 전 인스턴스에 적용.

main.ahk: Class와 정확히 같은 이름의 클래스 하나가 Plugin을 상속(extends Plugin)해서 선언한다. 예시(docs\Plugin\examples\HelloPacks\main.ahk 그대로):

class HelloPacks extends Plugin {
    static hookTarget := "PackOpening"

    afterEvent(ctx) {
        this.Log("팩 열림 감지")
    }
}

이게 끝이다 - 별도 등록 함수를 부를 필요 없다. static hookTarget으로 어느 기능에 붙을지 선언하고, 아래 카탈로그 표에서 그 타겟이 지원하는 beforeEvent/afterEvent/onItem 중 필요한 것만 override하면 엔진이 로드 시점에 인스턴스를 만들어 알아서 호출해준다.

훅 타겟 카탈로그 (17개)

범용 메서드 3개

Plugin을 상속하면 아래 3개 메서드를 override할 수 있다(부모 기본값은 전부 no-op):

  • beforeEvent(ctx) - 그 hookTarget이 before를 지원하면 시작 직전에 호출.
  • afterEvent(ctx) - after를 지원하면 끝난 직후에 호출.
  • onItem(ctx) - onItem을 지원하면(FriendAdd/FriendRemove/SpecialMission/Showcase), 항목 하나(친구 ID/이벤트명/쇼케이스 ID 등)를 처리할 때마다 호출.

한 클래스 안에서 그 hookTarget이 지원하는 메서드는 몇 개든 동시에 구현 가능하다(하한 1개 - 아무것도 구현 안 하면 검증에서 걸린다, 상한은 그 타겟이 지원하는 메서드 개수). 지원 안 하는 메서드를 구현해도 에러는 아니고 그냥 안 불린다(검증 단계에서 경고만 남음).

ctx.Get(key, default) - 조건부 필드 안전 접근

위 표의 필드 중 다수는 조건부다 - 예를 들어 RunPhase.after의 state는 Prepare/Finish 단계에서만 존재하고, GodPack.after의 cards는 폴백 경로면 빈 문자열이다. 이런 조건부 필드를 ctx.필드명으로 직접 읽으면, 없는 순간엔 AHK v2가 PropertyError를 던진다.

Fire()는 훅을 부르기 직전에 모든 ctx에 Get(key, default := "") 메서드를 자동으로 붙인다 - session.get()/botConfig.get()과 같은 관례다:

value := ctx.Get("state", "")       ; 없으면 예외 대신 ""
count := ctx.Get("count", 0)

반드시 있는 게 확실한 필수 필드(예: FriendAdd.onItem의 id, RunPhase.before의 phase)는 ctx.필드명으로 직접 읽어도 안전하다 - 조건부 필드에만 ctx.Get()을 쓸 것. Plugin.ahk의 Plugin.CTX_SHAPES가 "target.when → 실릴 수 있는 필드명 전체집합"의 실제 정의처다(이 문서는 그걸 프로즈로 옮겨 적은 사본). 코드가 CTX_SHAPES에 없는 필드를 실으면 PluginEngine.Fire()가 자동으로 Logs\Plugins.txt에 경고를 남긴다 - "문서/카탈로그가 코드를 못 따라간" 신호다.

주의: Fire()가 ctx에 Get을 매번 DefineProp으로 붙이기 때문에, ctx 자체를 JSON.stringify(ctx)로 그대로 직렬화하면(Dump(ctx) 포함) Get도 같이 열거되면서 Scripts/lib/JSON.ahk의 기존 버그(프로퍼티 열거와 개수 판정 기준이 서로 달라 trailing comma가 남는 등)가 미묘하게 튈 수 있다. 디스코드 웹훅 등 외부로 ctx를 보낼 땐 ctx를 통째로 넘기지 말고, 필요한 필드만 골라 새 객체로 추려서 보낼 것.

개발자 편의 함수 4개

게이트(SessionRead 등)와 별개로, 개발 중 관측/디버깅용으로 Plugin이 제공하는 인스턴스 메서드 4개다. 반드시 beforeEvent/afterEvent/onItem 안에서만 호출할 것 - this._name은 로더가 인스턴스 생성자(__New()) 실행이 끝난 뒤에야 채워 넣기 때문에, __New()를 override해서 그 안에서 이 함수들을 부르면 _name이 아직 빈 값이라 깨진다(__New()를 꼭 override해야 한다면 super.__New()를 맨 먼저 호출할 것 - 안 그러면 _timers Map이 없어서 TimerStart/TimerEnd도 깨진다).

메서드용도근거/재사용
Log(message, level := "info")관측용 값을 별도 파일에 기록 - "행 걸리는 게 관측돼서 로그 남기고 싶을 때"용. 엔진 자동 로그(Logs\Plugins.txt, 로드/진입/결과)와 분리된 Logs\Plugins_Dev.txt에 쓴다 - 자동 로그가 세션당 수백 줄일 수 있어서, 개발자가 직접 남긴 메시지가 그 안에 묻히지 않게. level은 "info"/"warn"/"debug" 등 기존 레벨 그대로.Scripts/lib/Logging.ahk의 LogMessage(level, message, logFile)를 그대로 씀(신규 로깅 메커니즘 없음)
TimerStart(label) / TimerEnd(label)코드 두 지점 사이 소요시간 측정 - TimerStart("x")를 앞에, TimerEnd("x")를 뒤에 두면 그 사이 걸린 ms를 계산해서 자동으로 Log()까지 남기고 반환도 해준다. 라벨별로 여러 구간 동시 측정 가능(인스턴스별 - 플러그인끼리 라벨 안 겹침).A_TickCount 기반 - "수 초 이상 걸리는 블로킹 금지" 규칙 위반 자가진단용으로 특히 유용
Dump(value, label := "")객체/배열/Map을 사람이 읽을 수 있는 문자열로 직렬화해서 Log()로 남김. AHK v2엔 console.log 같은 게 없어서, ctx.cards(배열) 같은 복합 값을 볼 때 유용 - ctx.cards.ToString()은 의미 없는 값이 나온다.Scripts/lib/JSON.ahk의 JSON.stringify(obj, expandlevel, space) 재사용(신규 직렬화 로직 없음)
Screenshot(label := "")현재 에뮬레이터 창을 캡처해서 Screenshots\Plugins\에 저장하고 경로를 Log()로 남김 - "행 걸린 것 같은데 그 순간 화면이 어땠는지" 눈으로 확인하고 싶을 때. 코어가 stuck 감지 시 이미 똑같은 패턴을 씀(SaveStuckScreenshot, Screenshots\Stuck\에 저장) - 그 방식을 플러그인용으로 그대로 재사용, 폴더만 분리.GDIPService.CaptureWindow(hWnd) + Gdip_SaveBitmapToFile

이 4개 다 실패해도(창을 못 찾음, 라벨 오타 등) 조용히 빈 값/0을 반환하고 로그만 남긴다 - 개발자 편의 함수가 던진 예외 때문에 3진아웃에 걸려서 원래 보려던 훅 자체가 꺼지면 본말전도이므로, 내부에서 방어적으로 처리한다.

타겟+메서드 충돌 규칙

같은 hookTarget + 같은 메서드(beforeEvent/afterEvent/onItem)를 구현한 플러그인이 2개 이상이면, 그 메서드만 딱 1개(승자)만 동작하도록 제한한다 (나머지는 무시).

  • 승자 판정: 클래스명 알파벳순(오름차순, 첫 번째가 승자) - 폴더명이 아니라 클래스명 기준. 폴더명은 보통 사용자 닉네임이라 조정하기 어렵지만, 클래스명은 개발자가 자유롭게 짓기 때문에 우선순위를 스스로 조절하고 싶으면 이름 앞에 A_/Z_ 같은 접두사를 붙이면 된다.
  • 진 쪽 처리: 플러그인 전체가 아니라 충돌난 그 메서드 호출만 생략. 같은 타겟에서 구현한 다른(무충돌) 메서드나, 다른 hookTarget에 대해 만든 별도 플러그인은 전혀 영향 없음.
  • 3진아웃과의 관계 - 대타 없음: 승자가 나중에 3회 연속 실패해서 세션 내 비활성되면, 그 target.when은 그냥 안 불리게 된다 - 진 쪽(2등)이 승계하지 않는다. 충돌 판정은 StartBot(로드 시점) 1회만 계산되고 런타임에 다시 안 돈다 - 승자 교체가 필요하면 사용자가 직접 승자 플러그인을 고치거나 꺼야 한다.
  • 예외: PropertyError/MethodError는 1회만에 즉시 비활성: 위 "3회 연속 실패"는 일반 예외(네트워크 타임아웃 등 일시적 오류) 기준이다. PropertyError/MethodError(존재하지 않는 프로퍼티/메서드 접근)는 결정론적이다 - 재시도해도 매번 똑같이 실패하므로, 3회 유예 없이 1회 실패만으로 그 훅이 세션 내내 비활성된다. 실무 함의: 조건부 필드(예: Wonderpick.after의 picked는 CreateBots 경로에만 실리고 EventMission 경로엔 없음)를 ctx.필드명으로 직접 읽는 플러그인은, 그 필드가 없는 호출 단 한 번으로 세션 내내 죽는다 - 위에서 설명한 ctx.Get(key, default)을 쓰면 이런 사고를 피할 수 있다.
  • 인스턴스별 결과가 다를 수 있음: Instances= ini 키로 참여 인스턴스가 플러그인마다 다르면, 워커 번호마다 승자가 달라질 수 있다. Plugin Manager UI의 정적 검사는 "전 인스턴스에 다 등록된다고 가정했을 때"의 충돌만 보여주므로, 실제 워커별 결과와 다를 수 있다.
  • Plugin Manager UI 표시: 상태 컬럼에 ⚠️가 뜨고(구조는 정상이나 메서드 일부가 다른 플러그인에 밀려 비활성), 그 행에 마우스를 올리면 어떤 메서드가 누구한테 밀렸는지 호버 툴팁으로 색 강조되어 보인다(아래 "Plugin Manager UI" 절 참고).

훅 실행 타임아웃

플러그인 훅이 멈춰서 안 돌아오면(무한 루프, Sleep 오남용 등) 워커 전체가 같이 멈춘다 - 이걸 잡는 워치독이 엔진에 있다. HOOK_TIMEOUT_MS(5분)를 넘게 한 훅이 안 끝나면, 신규 재시작 경로 없이 기존 stuck 복구 경로 (restartGameInstance, 스크린샷 저장 SaveStuckScreenshot, 계정 정리 예약 등)를 그대로 태워서 워커를 강제 재시작한다.

한계(반드시 인지할 것): AHK v2는 단일 스레드라 이 워치독(SetTimer 콜백)은 지금 도는 스레드가 "끼어들 수 있는 지점"(Sleep, 메시지펌프 등)에 있을 때만 발동한다. Sleep 한 번 없는 순수 타이트 루프(Loop { }에 아무 대기도 없는 경우)는 이 워치독으로도 못 끊는다 - 완벽한 강제 종료가 아니라 최선의 방어선이다. 다만 이 프로젝트의 실제 폴링 코드 (FindImageWithAction 등)는 전부 Sleep 기반이라 실질적으로 대부분의 "행" 상황엔 먹힌다.

ctx.phase 값 4개 - RunPhase의 before/after에서만 온다

플러그인이 "어디에 붙을지"를 고르는 건 static hookTarget이다(예: hookTarget="RunPhase"로 선언하면 RunPhase의 before/after에 붙는 것). phase는 그 중 RunPhase 타겟에 한해서, 지금 코어가 어느 단계를 도는 중인지 알려주는 ctx.phase 값일 뿐이다. 대상 파일은 module\classes\PackOpeningRun.ahk의 static 메서드 4개와 1:1이다.

크로스 플러그인 참조

다른 플러그인의 인스턴스를 얻으려면 this.GetPlugin("다른플러그인명") (인스턴스 메서드 - 내부적으로 PluginEngine.GetPlugin을 얇게 감싼다). 이름은 클래스명이 아니라 폴더명(plugin.ini의 Name)이다. 그 플러그인이 꺼져있거나 없으면 ""을 돌려주므로 반드시 if (other := this.GetPlugin("X"))처럼 방어할 것. 훅 안(beforeEvent/ afterEvent/onItem)에서만 호출할 것 - 파일 최상위에서 부르면 include 순서에 따라 아직 그 플러그인이 로드 안 됐을 수 있다.

상태 저장 - 두 층

  • 세션 중만 유지되면 되는 값: 클래스의 인스턴스 필드(this.someField) - 플러그인마다 인스턴스를 하나씩 만들므로 this.xxx를 쓴다. 플러그인 코드는 워커 프로세스 안에 상주하므로 이미 봇의 세션(session)과 같은 수명이다 - 별도로 등록/왕복할 필요가 없다.
  • 워커 재시작(리로드/재접속) 뒤에도 남아야 하는 값: this.SaveValue("키", 값) / this.LoadValue("키", 기본값). 인스턴스 자기 Scripts\N.ini의 [Plugin_내폴더명] 섹션에 쓴다 - 섹션 이름 자체가 소유권이라 다른 플러그인 값과 안 섞인다.

봇 상태(session/botConfig) 접근

  • 읽기: this.SessionRead(키), this.ConfigRead(키) - 둘 다 자유롭게 읽을 수 있다.
  • 쓰기: this.SessionWrite(키, 값) - 화이트리스트에 있는 키만 성공한다(지금은 keepAccount 하나뿐). 화이트리스트에 없는 키는 조용히 거부되고 Logs\Plugins.txt에 경고가 남는다. botConfig는 쓰기 API 자체가 없다(설정 저장은 plugin.ini를 직접 쓸 것).
  • SessionRead()가 돌려주는 값이 배열/Map 같은 객체면 읽기 전용으로만 다룰 것 - 내부 내용을 고치면 코어 상태가 그대로 오염된다.
이 게이트는 보안이 아니라 난간이다. AHK v2엔 private이 없어서 session.set()을 직접 불러 우회할 수 있다 - 가치는 허용 범위가 코드로 문서화되고, 위반이 로그에 남아 진단이 빨라진다는 것뿐이다.

지켜야 할 것 (안 지키면 워커가 멈추거나 죽을 수 있음)

  1. 훅 안에서 FindImageWithAction을 부를 땐 count: 1 또는 giveUpTime을 반드시 넣을 것. 기본값(count: -1, 무한 폴링)으로 부르면 니들이 안 나타났을 때 워커가 그 훅 안에 영원히 갇힌다.
  2. ExitApp / Reload / Pause 호출 금지 - 워커가 즉사/정지한다.
  3. SetTimer / Hotkey 등록 금지 - 코어 화면 조작 도중 인터리브되면 클릭 레이스가 난다.
  4. session.run.xxx 같은 owner 객체 직접 접근 금지 - 위의 게이트 함수만 쓸 것.
  5. 수 초 이상 걸리는 블로킹 Sleep 금지 - 훅은 코어 런 루프 한복판에서 돈다.
  6. 전역 함수/변수/니들 이름에 자기 플러그인 접두사를 붙일 것(예: MyPlugin_ 또는 EBC_). 코어나 다른 플러그인과 이름이 겹치면 로드 자체가 실패해서(아래 검증 단계에서) 그 플러그인이 통째로 제외된다.
  7. 게이트(SessionRead/SessionWrite/ConfigRead/SaveValue/LoadValue/GetPlugin)와 개발자 편의 함수(Log/TimerStart/TimerEnd/Dump/Screenshot)는 beforeEvent/afterEvent/onItem 안에서만 호출할 것 - __New()(생성자) 안에서 부르면 this._name이 아직 안 채워져서 깨진다(위 "개발자 편의 함수" 절 참고).

검증 - StartBot마다 자동으로 일어남

  1. 폴더 스캔, Name=폴더명 확인.
  2. plugin.ini의 Class= 키 필수 확인, main.ahk 안에 class <Class값> extends Plugin 선언이 있는지 정규식으로 확인.
  3. static hookTarget := "..." 값이 위 훅 타겟 카탈로그(17개) 중 하나인지 확인.
  4. beforeEvent(/afterEvent(/onItem( 중 최소 1개 구현했는지 정규식으로 확인 → 없으면 통과 실패. 타겟이 지원 안 하는 메서드를 구현했으면 통과는 하되 Logs\Plugins.txt에 경고만(치명적 아님, 그냥 안 불림).
  5. 같은 hookTarget+메서드를 구현한 다른(활성화+구조 정상) 플러그인과 충돌하는지 계산(위 "타겟+메서드 충돌 규칙" 절) - 이 결과를 Plugin Manager UI의 ⚠️ 표시와 호버 툴팁이 그대로 쓴다.
  6. 동봉된 .png는 Scripts\Needles\에 없는 것만 복사(출하 이미지는 덮어쓰지 않음).
  7. 이미 통과한 플러그인들 + 이번 후보를 합쳐서 1.ahk 전체를 실제로 실행하지 않고(파싱만) 검사 - 문제 있으면 이번 후보만 제외되고 나머지는 그대로 진행.
  8. 하나라도 제외되면 트레이 알림 1개 + Logs\Plugins.txt에 사유(뭘 고쳐야 하는지까지) 기록.

plugin.ini의 Enabled=0이나 폴더를 지우는 것만으로 다음 StartBot부터 제외된다.

Plugin Manager UI (PTCGPB.ahk)

plugin.ini를 직접 안 고쳐도 되도록 관리 화면이 있다: 메인 창 → 🧩 도구 아이콘 → Tools & System Settings → 🧩 Plugin Manager 버튼.

  • 목록: Plugins\ 아래 폴더를 전부 보여준다(꺼져있는 것도 포함). 맨 왼쪽 체크박스가 활성화 여부, 두 번째 칸이 상태 - ✅ 정상(구조 검증 통과 + 충돌 없음 + 죽은 플러그인 아님) / ⚠️(구조는 정상이나 메서드 일부가 다른 플러그인에 밀려 비활성 - 사유 칸에 "afterEvent: <승자 클래스명>에 밀림" 형태로 표시 - 충돌 승자 판정 자체가 클래스명 기준이라 클래스명으로 표시한다) / ❌(구조 검증 자체 실패 + 사유). 실제로 워커에 로드 가능한지(문법 오류 등)까지는 여기서 안 본다 - 그건 StartBot 시점에 확정된다.
  • 🔴 죽은 플러그인: 구현한 메서드가 전부 그 hookTarget이 지원 안 하는 메서드뿐이라 하나도 안 불리는 경우, 이름 앞에 🔴 접두사가 붙고 상태 컬럼에 ❌ 호출 가능한 메서드 없음이 뜨며, plugin.ini의 Enabled 값과 무관하게 체크박스가 항상 기본 미체크로 그려진다(직접 다시 체크하는 건 막지 않음 - 어차피 아무 메서드도 안 불리니 해가 없다).
  • ⚠️/🔴 행 호버 툴팁: 행 위에 마우스를 올리면 어떤 메서드가 누구한테 밀려서 실행이 안 되는지(충돌), 또는 어떤 메서드가 이 타겟에서 허용되지 않는지를 색 강조된 팝업으로 보여준다.
  • 🔄 새로고침: 목록을 다시 스캔한다. 파일을 안 건드리는 순수 조회라 빠르다.
  • 🗑 삭제: 목록에서 행 하나를 클릭해 선택한 뒤 누르면 그 플러그인 폴더 전체를 지운다. 비활성화(체크박스 해제)와 달리 되돌릴 수 없어서 확인 대화상자를 거친다. 이때 그 플러그인이 동봉했던 니들 이미지도 Scripts\Needles\에서 같이 지우되, 다른 남아있는 플러그인이 같은 파일명을 쓰고 있거나 NeedleRegistry.ahk에 등록된 코어 니들 이미지명과 같으면 지우지 않는다(둘 중 하나라도 확실치 않으면 안 지우는 쪽을 택함 - Logs\Plugins.txt에 왜 안 지웠는지 남는다).
  • 적용/저장: 체크박스 상태를 각 plugin.ini의 Enabled에 즉시 쓴다. 다음 StartBot부터 반영되고, 지금 떠있는 워커에는 영향 없다.
