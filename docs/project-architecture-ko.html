1. 프로젝트 개요

1.1 이 봇이 하는 일

포켓몬 TCG 포켓(PTCGP) 모바일 게임 자동화 봇이다. MuMu 에뮬레이터 안에서 게임을 여러 인스턴스로 띄워 돌린다. 화면은 템플릿 이미지 매칭("니들" 검색)으로 읽고, 게임 조작은 ADB shell 입력으로 한다. 주요 기능:

  • 팩 개봉 리롤: 새 계정을 만들거나(Create Bots 13P) 저장된 계정 XML을 주입해서(Inject 모드) 팩을 열고, 갓팩/거래 가능 카드/위시리스트 카드를 감지한다.
  • 갓팩 검증(GP Test): Main.ahk 인스턴스가 원더픽 화면을 통해 친구 목록의 갓팩 계정을 검증한다.
  • 친구 관리: 친구코드로 추가, 전체 삭제, 요청 승인, 쇼케이스 좋아요(Stage\FriendManager.ahk).
  • 미션/보상: 일일 미션, 초보자 미션 반복, 선물 팩, 원더픽, 이벤트 보상(Stage\MissionAndRewards.ahk).
  • 계정 관리: 계정 XML 추출/주입, 계정별 JSON 메타데이터(팩 수/플래그/샤인더스트), 스케줄링/자격 판정, 스냅샷 및 손상 복구.
  • 모래시계 소모(HourglassSpend), 위시리스트 매칭(Wishlist), 디스코드 웹훅 알림, 웹 카드 대시보드, 서드파티 플러그인 시스템(hookTarget 17개).

1.2 기술 스택

영역기술비고
언어/런타임AutoHotkey v2.0v1에서 이식. v1의 버그 몇 개는 의도적으로 그대로 보존한다(예: selectMsg, PTCGPB.ahk:85-93).
에뮬레이터MuMu Player (Global/12, v4/v5)창 클래스는 Qt5156QWindowIcon. 인스턴스 제어는 MuMuManager 채널, 게스트 제어는 ADB 채널 — 이 둘은 절대 섞이지 않는다(Emulator.ahk 헤더 주석).
기기 제어ADB (상주 shell + su)WScript.Shell.Exec로 adb shell을 상주시킨다. 모든 명령은 done 마커 줄로 완료를 감지한다.
화면 인식GDI+ (PrintWindow 캡처 + Gdip_ImageSearch)PW_CLIENTONLY|PW_RENDERFULLCONTENT를 써서 가려지거나 백그라운드에 있는 창도 캡처한다.
카드 판독adv_pocket_tool(안드로이드 헬퍼 바이너리) + Windows OCR + 테두리 검출티켓 기반 결과 파일 폴링. 테두리(RarityBorder) 경로는 OCR이 실패했을 때만 돈다.
카드 아트 호스팅Cloudinary (res.cloudinary.com/crinitycloud)2026-08-10에 crinitys.github.io에서 이관 — 이미지 약 1만4천장 때문에 GitHub Pages 1GB 발행 한도를 넘어섰던 게 원인. 로컬 캐시는 Cache\CardImageCache\<lang>_<country>\ 언어별 하위폴더(§9.3 참고).
네이티브 가속MCode(임베디드 x64 머신코드)lib\JsonScanMCode.ahk — 계정 JSON 스캔 19.8초 → 0.4초(실측, 계정 6,094개 기준).
웹 서버thqby HttpServer(네이티브 AHK, IOCP)예전 Rust carddb.exe(axum)와 PowerShell HttpListener 스크립트를 대체.
알림디스코드 웹훅Diagnostics.Discord + DiscordLogger.ahk 파사드.
검증 도구.bin\AutoHotkey64CLI.exe(로컬 빌드, gitignore됨)헤드리스 AHK 로드/런타임 검증 — 경고와 처리 안 된 예외 전부 대화상자 없이 stderr로만 출력, 처리 안 된 예외는 exit 1.

1.3 반복되는 설계 패턴

  • 파사드 보존 리팩토링: 자유함수 뭉치를 클래스(정적 네임스페이스)로 옮기되, 기존 호출부(수백~1,600곳)를 위해 같은 이름·시그니처의 얇은 위임 래퍼를 남긴다. 예: ADB.ahk→Emulator, Utils.ahk 일부→Host, Logging/Profiler/DiscordLogger→Diagnostics, Recognition\CardDetection.ahk→PackAnalysis.
  • 메커니즘/정책 분리: ScreenSearch(순수 검색 메커니즘)는 실패 복구 정책을 갖지 않는다. FindImageWithAction(정책 계층)이 멈춤 복구(restartGameInstance)를 소유한다.
  • 로드 시점 의존성 스텁: AHK v2는 함수 몸통이 정의되지 않은 이름을 참조하면 로드 시점에 조용히 멈춘다. 그래서 Cockpit/LaunchAllMumu는 무거운 진짜 Host/Emulator를 끌어오는 대신, 정적 로드 검사만 통과시킬 최소 스텁 클래스를 선언한다. (Monitor.ahk도 원래 스텁을 썼지만, 실제로 런타임에 Emulator.GetInstallFolder()를 호출한다 — 빈 스텁 탓에 2026-08-07에 "MuMu 폴더 없음" 오탐 종료가 실측됐고, 지금은 진짜 클래스를 끌어오고 CreateStatusMessage만 스텁한다.)
  • 원자적 파일 쓰기: tmp 파일에 쓴 뒤 FileMove(…, 1)로 교체 — Metadata/History/AccountStore/CockpitState 전반에서 일관되게 쓴다. Scripts\N.ini는 의도적으로 이 방식을 안 쓴다 — 다중 생산자 파일이라, 전체 재작성 커밋은 그 사이 다른 경로가 쓴 키를 되돌려버린다(CockpitInstancePush.ahk 헤더에 문서화됨).
  • 자기 의존성 선언: 라이브러리 파일은 %A_LineFile% 기준으로 자기 의존성을 스스로 #Include한다 — 어느 진입점이 끌어오든 경로가 깨지지 않는다.

4. Scripts\lib\ — 범용 라이브러리 계층

ScreenSearch.ahk — 니들 검색 서비스 (정책 없음)

  • Search(hwnd, needleName, opts): 1회성 캡처+검색. 매치 위치("x,y") 또는 false 반환. 캡처한 프레임에 대해 ErrorCheckInScreen을 동적 조회로 호출(에러 모듈을 include 안 한 호출부는 조용히 건너뜀 — 조회만 try로 감싸고, 실제 Call은 삼키지 않음).
  • SearchIn(bmpPointer, imageName, x1,y1,x2,y2, variation): 이미 캡처된 프레임을 재검색(같은 프레임에 니들 N개를 대도 캡처는 한 번만 든다).
  • SearchWithAction(hwnd, needleName, actionFn, opts): 찾을 때까지 actionFn 반복. pollIntervalMs(기본 100)와 actionIntervalMs가 분리돼 있어(원래의 "100ms마다 검색, sleepTime ms마다 클릭" 분할을 재현), giveUpTimer(만료→false 반환), stuckTimer+onStuck(만료→교정 콜백 후 Reset — 루프는 계속 돔).

  • 왜 여기 복구 정책이 없나: Search/SearchWithAction은 순수 메커니즘이다. Timer를 만들고 Expired()가 뭘 뜻하는지(포기 vs 재시작) 결정하는 건 각 호출부의 몫 — 그 정책 계층이 FindImageWithAction이다.

9.2 카드 아트 파이프라인 — Cloudinary 이관 (2026-08-10)

카드 아트는 원래 crinitys.github.io에서 서빙됐는데, 이미지 약 1만4천장 때문에 그 저장소가 GitHub Pages 1GB 발행 한도를 넘어서서, 원본을 Cloudinary로 다시 올렸다. 이제 소비자 둘 다 같은 URL 형태를 쓴다: https://res.cloudinary.com/crinitycloud/image/upload/images/<lang>_<country>/<illustrationId>.png (버전 세그먼트 불필요 — 실제 호스트로 실측 확인됨):

  • 봇 쪽: PackAnalysis.Render.GetCardArtImage(illustrationId, lang, country, cacheDir)(PackAnalysis.ahk:1223) — 디스코드에 올릴 합성 팩 이미지용으로 카드 한 장의 아트를 다운로드하며, PNG 시그니처로 응답을 검증한다(그렇지 않으면 200 응답의 HTML 안내 페이지가 "유효한" 이미지로 영구히 캐시될 수 있음).
  • 대시보드 쪽: Route_CardImagesPrefetch.ahk("Use local card images") — Helper\cardmap.json의 모든 고유 illustrationId를, 타이머로 펌프되는 비동기 WinHttpRequest 약 20개 동시 실행으로 일괄 프리페치한다(AHK는 단일 스레드라서 수천 장을 순차 다운로드하면 수십 분 걸림). 202 + 폴링용 /card-images/status를 반환하고, 서버가 멈추면 다운로드도 같이 멈춘다(DashboardServer.OnStop).

9.3 로케일별 이미지 캐시

다운로드 캐시는 Cache\CardImageCache\<lang>_<country>\<illustrationId>.png다 — 2026-08-10부로 로케일별 하위폴더로 분리됐는데, 일부 카드가 언어마다 같은 illustrationId에 다른 그림을 쓰기 때문이다. 폴더 하나로 합쳐놨을 때는 언어를 바꿔도 이전 언어의 캐시된 아트가 그대로 반환됐다(사용자 실측 제보). 소비자:

  • 봇은 로드된 계정의 언어 메타데이터에서 로케일을 고른다(GetCardArtImage의 lang/country 인자로).
  • 대시보드는 계정 맥락이 없어서, 호스트 GUI(DashboardServerHost.ahk)가 11개 로케일 선택기(en_US … id_ID)를 제공해 DashboardServer.CardImageLocale을 설정한다 — 프리페치와 서빙 둘 다 이 값을 기준으로 한다.
  • 브라우저로의 서빙은 GET /card-image/<illustrationId>(Route_CardImage.ahk, RoutePrefix 라우트)를 거친다 — 옛 페이지는 캐시 폴더를 직접 GET했는데, 이건 설치 폴더 전체가 웹 루트였기 때문에만 가능했다. 이 라우트는 id를 세탁하고, 캐시 폴더 밖으로 벗어나는 경로는 거부하며, public, max-age=86400으로 서빙한다(카드 아트는 절대 안 바뀌므로).

10.4 ADB 명령 실행 — 상주 셸 vs 별도 프로세스

[상주 셸 확립: Emulator.InitializeShell()]
  WScript.Shell.Exec("adb -s 127.0.0.1:<port> shell")   ← 상주 프로세스 하나
  → StdIn.WriteLine("su")                                  ← 루트 권한
  → 실패 시: disconnect/connect(CmdRet = 별도 프로세스), 이후 백오프 재시도(최대 5회)

[일반 명령: Emulator.RunAdbCommand(command, isReturnning, timeoutMs)]
  StdIn.WriteLine(command . ";echo;echo done;")
    ─ 핵심은 맨 앞의 빈 echo: 출력이 개행으로 안 끝나는 명령(cat 등)은
      마커가 "…}done"처럼 붙어버려서 ReadLine이 영원히 블록될 수 있는데,
      빈 echo가 마커를 반드시 자기 줄로 시작하게 보장한다
  Loop StdOut.ReadLine():
    line = "done"  → 완료(isReturnning이면 누적된 출력 반환)
    타임아웃 체크  → 줄 사이에서만 발동. 셸이 완전히 침묵하면
                     ReadLine이 COM 호출 안에서 블록됨 — 이 경우는 여전히
                     걸림, 유일한 신호는 "done"이 안 붙은 "send" 트레이스뿐(소스 주석)
    죽은 셸        → InitializeShell()로 재연결 후 재시도
  실패 시: 최대 3회 재시도, 소진했을 때만 adbShell 리셋 + EnsureShell()
    (예전엔 catch가 무조건 셸을 리셋해서, 다음 반복이 매번 "String has no StdIn"으로
     죽었다 — 실측 주석에 따르면 재시도 실패 3건 중 2건이 이 자체-리셋으로 인한 것)

[별도 프로세스로 도는 명령들, 그리고 그 이유]
  · adb connect / disconnect (CmdRet)
      → 연결 자체를 만들고 끊는 명령이라, 그 연결 위에서 사는
        상주 셸을 탈 수가 없다
  · DisableBackgroundServices 안의 pm disable-user 명령 4개
      → 각각 독립적으로 "adb -s ... shell pm ..."을 실행 — 상주 셸이

  · Emulator.TerminateAdbProcesses
      → ProcessClose+taskkill로 호스트의 adb.exe 자체를 죽임(채널 명령이 아니라
        호스트 프로세스 제어)
  · MuMuManager 채널(RunManagerCommand: launch/shutdown/restart/setting)
      → 게스트가 꺼져 있어도 동작해야 하는 인스턴스 레벨 제어 — ADB와
        실패 모드가 달라서 범용 RunCommand 래퍼가 따로 없다(Emulator.ahk 헤더)

(2) 도메인 클래스(module\classes\*)는 자기 include를 갖지 않는다 — 진입점이 include 목록을 소유하며, 이 덕분에 Cockpit의 스텁 대체가 가능했고, 7개 폴더 재분류도 순수한 경로 변경으로 끝날 수 있었다. (3) 일부 모듈 간 호출(ErrorCheckInScreen, bboxAndPause_immage)은 %"name"% 동적 조회로 풀려서, 선택적 의존성이 된다. (4) 플러그인 매니페스트는 #Include *i(선택적)로, botConfig 대입 이후에 include된다 — 플러그인 등록 로그가 호출 시점에 botConfig를 읽는 Diagnostics를 거치기 때문.

13. 플러그인 시스템 (module\Plugin\)

2026-08-09에 도입된 서드파티 확장 지점으로, 이제 전용 폴더 Scripts\module\Plugin\에 자리한다. 저장소 루트 Plugins\ 디렉터리 밑의 폴더 하나가 플러그인 하나이며, StartBot마다 PTCGPB.ahk의 PluginEngine_GenerateManifest()(2951행, 2658행에서 호출 — 한 번만, 워커 복사 전에. 모든 인스턴스가 생성된 파일 하나를 공유하므로)가 이를 스캔·검증한 뒤 Scripts\_plugins.g.ahk로 인스턴스화 코드를 생성한다. 워커는 이걸 #Include *i로 끌어와서, 매니페스트가 없어도 단독 로드가 절대 깨지지 않는다. 전체 사용법과 API 레퍼런스는 docs\Plugin\README.md(한국어)/README-en.md(영어) 참고 — 이 절은 아키텍처만 요약한다.

13.1 역할 분담 — Plugin vs. PluginEngine

  • Plugin\Plugin.ahk(154줄): 플러그인 작성자가 상속하는 부모 클래스. 훅 타겟 카탈로그(HOOK_TARGETS, 17개)와 각 target.when이 실을 수 있는 ctx 필드 카탈로그(CTX_SHAPES, 35개 항목), 상태 접근 게이트(SessionRead/SessionWrite/ConfigRead/SaveValue/LoadValue/GetPlugin), 개발자 편의 함수(Log/TimerStart/TimerEnd/Dump/Screenshot — 전부 자기 실패를 삼킨다, 그래야 디버깅 헬퍼가 자기가 살펴보던 훅을 3진아웃시키는 일이 없다)를 소유한다.
  • Plugin\PluginEngine.ahk(271줄, 18.9KB): 인스턴스 등록(RegisterInstance), 충돌 해결(ResolveConflicts), 발화(Fire), 타임아웃 워치독(CheckHookTimeout)을 소유한다. Plugin.ahk의 카탈로그를 참조만 하고 사본을 갖지 않는다 — "정의는 Plugin, 검사·발화는 PluginEngine".
  • 훅 타겟 17개: RunPhase/Wonderpick/FriendAdd/FriendRemove/InstanceRestart/DailyMission/SpecialMission/Gift/Hourglass/Showcase/PackOpening/GodPack/AccountExhausted/StuckRestart/BeginnerMission/Tutorial/FoundTradeableCard — 각각 자기 타겟이 지원하는 beforeEvent(ctx)/afterEvent(ctx)/onItem(ctx)를 오버라이드한다(onItem은 항목 단위 타겟 4개에만 존재: FriendAdd/FriendRemove/SpecialMission/Showcase).

13.2 ctx 드리프트 감지 — 문서/코드 불일치 자동 포착

Fire()가 훅을 호출하기 직전, 실제 ctx의 필드를 Plugin.CTX_SHAPES 선언과 비교해서 선언 안 된 필드가 있으면 Logs\Plugins.txt에 경고를 남긴다(_CheckCtxDrift) — "코드가 카탈로그보다 앞서갔다"는 신호. 모든 ctx엔 DefineProp으로 Get(key, default)가 자동으로 붙어서, 조건부 필드(예: GodPack.after의 cards, 폴백 경로에서는 빈 문자열)를 안전하게 읽을 수 있다 — session.get()/botConfig.get()과 같은 관례. 풍부한 페이로드로는 PackOpening.after(cards/shinedust/pack/lang/country/raw/stopEarly)와 StuckRestart.before(reason/callerFile/callerLine/RL)가 있다.

13.3 안전장치 네 가지

  • 3진아웃, 단 1진아웃 예외 있음: 같은 target.when에서 연속 예외 3번이면 그 세션 동안 비활성화. 다만 PropertyError/MethodError(존재하지 않는 프로퍼티/메서드 접근)는 결정론적이라(재시도해도 매번 똑같이 실패) 3진아웃 유예 없이 첫 발생 즉시 비활성화한다.
  • 충돌 해결: 같은 hookTarget+메서드를 플러그인 2개 이상이 구현하면 클래스 이름 알파벳순으로 먼저 오는 쪽이 이긴다. 진 쪽은 그 메서드만 조용히 스킵되지, 전체가 비활성화되진 않는다. 이 판정은 StartBot당 한 번뿐이다 — 이긴 쪽이 나중에 3진아웃돼도 진 쪽이 대신 넘겨받지 않는다.
  • 재진입 가드: CheckHookTimeout()이 멈춘 훅을 감지해 restartGameInstance()를 부르면, 그 호출 자체가 StuckRestart 훅을 발화시켜 Fire()에 재진입할 수 있다. currentHook을 진입 시 저장하고 끝나면 복원하므로, 워치독이 추적하던 바깥쪽(멈춘) 훅 정보가 재진입 호출을 거쳐도 살아남는다.
  • 타임아웃 워치독: HOOK_TIMEOUT_MS(5분)를 넘긴 훅은 기존 멈춤복구 경로(restartGameInstance)로 강제 재시작된다. 이건 SetTimer 콜백으로 돌기 때문에, Sleep 없는 순수 타이트 루프는 끊을 수 없다 — 최선을 다하는 보호이지 강제 종료는 아니다.
